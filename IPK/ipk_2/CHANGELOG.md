# CHANGELOG

## 1.0.0 - 2026-05-02

### Implemented functionality

- **Reliable UDP transport** - custom application-level protocol over UDP with cumulative ACK and SACK extension (up to 15 selective ACK blocks), providing reliable and ordered delivery
- **Pipelined sliding window** - fixed send window of 30 segments with selective repeat; only missing segments are retransmitted, not the full window
- **3-way handshake** - SYN / SYN-ACK / ACK session establishment with random connection ID and independent ISNs for client and server
- **4-way teardown** - FIN / FIN-ACK / ACK session termination with TIME_WAIT on the client side to absorb delayed retransmits
- **Integrity protection** - RFC 1071 Internet checksum over the full PDU (header + payload); corrupted or truncated packets are silently discarded
- **Connection identification** - random 32-bit `conn_id` generated by the client and validated on every incoming packet; unrelated packets are dropped
- **Exponential backoff retransmission** - initial interval 200 ms, multiplier ×2, ceiling 3000 ms; per-segment timers for data, shared timer for control packets
- **Progress timeout** - `-w TIMEOUT` terminates the session with a non-zero exit code if no protocol progress is observed for the specified number of seconds
- **IPv4 and IPv6** - DNS resolution via `getaddrinfo`; both address families supported for client and server
- **Flexible I/O** - client reads from a file or stdin; server writes to a file or stdout
- **Signal handling** - SIGINT and SIGTERM terminate the application cleanly without leaving temporary files
- **Implicit handshake ACK recovery** - if the client's third handshake ACK is lost, the server accepts the first data segment as an implicit completion, preventing stalls under packet loss
- **Automated tests** - Catch2 unit tests (packet, window, buffer, session, DNS, socket) plus shell-based end-to-end and tc-netem network-impairment test suites

---

## Known Limitations

- **No sub-second timeout granularity** - `-w` accepts only whole seconds; a 200 ms retransmit base with `-w 1` leaves little margin
- **Fixed window size** - no dynamic window sizing or receiver-advertised window; the sender does not back off if the receiver is slow
- **No ICMP error handling** - unreachable server is detected only via the progress timeout, not via ICMP port-unreachable
- **High loss rates (>40%)** - exponential backoff can reach the 3 s ceiling, making a `-w 5` timeout tight under repeated loss on the same segment
- **Single-client server** - exactly one session per process run; concurrent clients are not supported
- **No congestion control** - window size is fixed at 30 segments; no AIMD or BBR-style avoidance
- **No partial-transfer resume** - a killed transfer must be restarted from the beginning
- **No bidirectional transfer** - data flows client → server only
- **Segment-indexed sequence numbers** - simplifies SACK arithmetic but is incompatible with byte-stream-oriented protocol analysers
- **Violation of Pure Clean Architecture** - App directly touches Session, which is 2 layer jump. This violation of architecture is pretty well contained and if there would be the need to have better architecture, introduction of thin ITransport interface shouldn't take long.
